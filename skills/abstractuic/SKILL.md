# Use AbstractUIC

This skill describes the source revision. Compare the installed package and its
type declarations before using source features; the installed version's docs win.

Start with [the adoption guide](https://raw.githubusercontent.com/lpalbou/AbstractUIC/main/docs/adoption-guide.md) to choose an existing
component for the user-facing job. The repository ships multiple npm packages;
use the relevant package rather than importing a sibling app’s source.

Import `@abstractframework/ui-kit/theme.css` and, for chat,
`@abstractframework/panel-chat/panel_chat.css` in the host entry point. Use shared
theme tokens and `Icon`; keep the host’s appearance and connection state authoritative.
See [getting started](https://raw.githubusercontent.com/lpalbou/AbstractUIC/main/docs/getting-started.md) and [API](https://raw.githubusercontent.com/lpalbou/AbstractUIC/main/docs/api.md).

## Docs assistant and voice

Mount `DocsAssistantDrawer` from `@abstractframework/panel-chat` with `source`
(`app`, `name`), `connected`, `open`, `onClose`, and the host’s authenticated
`fetchGateway`. Keep it mounted while closed so its conversation survives.
The transport must support JSON writes and binary artifact reads, applying the
host’s session/CSRF or bearer authentication. Do not put credentials in component
state, localStorage keys, rendered markup or URLs.

The component resolves this app’s documentation through the Gateway and owns
its history, attachments and question lifecycle. It shows per-reply speech when
a voice route is configured. Pass `voicePreferences` when the app has overrides;
otherwise the Gateway default applies. Speech is manual, with play/pause/resume.
Opening past answers never speaks automatically. A rail host using
`docsAssistantPanel` should provide `visible` so hiding it stops playback.

Use `AfVoiceSection` for controlled engine, device, capture and playback settings;
`compact` fits narrow drawers. Preserve its `value`/`onChange` and reset semantics.
Use `useGatewayVoice` for playback/capture lifecycle instead of duplicating browser
audio state. Gateway synthesis owns models; components record/play locally.
See [panel-chat](https://raw.githubusercontent.com/lpalbou/AbstractUIC/main/panel-chat/README.md) and [ui-kit](https://raw.githubusercontent.com/lpalbou/AbstractUIC/main/ui-kit/README.md).

Tool and workspace controls express choices within Gateway limits. They cannot
grant a capability the Gateway forbids. Preserve blocked/error feedback and use
`AfTooltip` for brief, useful information; avoid repeating a label as help.

## Compact multiline chat input

Use `ChatComposer` with `variant="compact"`, or `WorkflowChat` with
`composerVariant="compact"`, for a rounded multiline composer. Omit the option
for the existing layout. Compact defaults to two rows and grows to a bounded
scrolling field; explicit `rows` remains the minimum. Keep host draft and submit
callbacks unchanged. Attachments use `leading`; attachment, microphone and Stop
controls keep their existing action slots and accessible labels. Do not replace
them with a separate composer or hide actions to make a narrow pane fit.

## Procedural avatar presentation

Use `ActivityAvatar` for any identifier from `await avatarDesigns()`. The 44-design
catalog is generated by AbstractAvatar; the browser component presents its bundled
Wasm output. Bind `active` to actual host visibility and `animated` to preferences;
hidden/reduced-motion views stop their animation clocks. Pass observed level in
0–1 and optional eight frequency bands, with no microphone or inference inside
the component. Settings previews may explicitly supply a sample level.

Confirm the installed type declarations expose `AvatarQuality` before passing
`quality`. Choose economy for multiple previews (256 px / 12 active fps), balanced
for one portrait (384 px / 24 active fps, the default), or high for a prominent
portrait (512 px / 30 active fps). These are upper budgets; pixel area and higher
cadence increase CPU work. Display-density changes rebuild the bounded renderer.
`followCursor` observes movement and clicks without consuming host actions. Only a
design whose catalog entry has `gaze: "eyes"` responds: its eyes ease toward the
pointer and back to centre after two idle seconds; the avatar never translates,
rotates or tilts, and every other design ignores the pointer. Gaze is disabled by
reduced motion, touch and non-Ready poses. Use `avatarGazeTarget` for the same rule
in a custom Canvas host.

For Canvas, create `AvatarRenderer`, pass a version-one object through
`parseAvatarFrame`, call `renderFrame`, then `dispose` when the view closes. A frame
contains `schema_version: 1`, `style`, `state`, bounded seconds `time`, and `level`;
optional `gaze` has two coordinates in −1–1 and `bands` has eight values in 0–1.
Absent bands use the scalar envelope. Descriptors contain data only; they cannot
select executable code, files or URLs. A custom Wasm `source` must be trusted local
AbstractAvatar bytes. Keep no more than 16 renderers live; page large galleries.
An optional `AbortSignal` cancels asynchronous creation with `AbortError` before
allocating a native handle. Dispose successfully created renderers explicitly.
See [Activity avatars](https://raw.githubusercontent.com/lpalbou/AbstractUIC/main/docs/avatars.md) for the full API and compatibility exports.

## Compact session lists

Use `SessionCard` for conversation rows and read `docs/session-cards.md` before integrating
unread state. Keep unread, human attention and working facts independent. Host applications
own transport and confirmation; reading must never resolve an approval or question.

## Public avatar conversation

`WorkflowChat.avatarConversation` adds an optional public view over the same controller,
draft and interactions. Omit it for ordinary chat. Use `conversationSnapshot(snapshot)`
for status, attention and replay guards; provide an owner-scoped `sessionKey`, actual
avatar and existing voice callbacks. `AvatarConversation` also works standalone.
Provide `interactionId` for a standalone view's actual pending request: the request
controls take priority with a smaller avatar, pinned above the live line. Use an
empty string for no request or a deferred request; omitted `interactionId` treats
a supplied interaction as active. `WorkflowChat` forwards its actual
interaction identity automatically.
Use `WorkflowInteractionPanel variant="conversation"` for public avatar requests, never
the default technical panel. `presentInteraction` supplies plain actions/targets and
checks `details.public_action` against the exact pending batch/run. `onTechnicalView`
on avatar options (or panel `onReviewTechnical`) opens the host’s detailed view without
answering. No raw reasoning or unrelated latest brève may supply the request’s reason.
Unknown actions need detailed review; standing grants stay in the technical view.
Public history accepts validated public updates, user messages and typed answers/finals;
never feed raw reasoning or private entity traces into the view. `conversationLive(messages)`
gives the ONE live line (the latest public update of the current turn, replaced as new ones
arrive) and the turn's answer, shown once; `conversationFindings(messages)` gives the
conversation's findings, newest last, with the results each cited. A finding is only an update
the actor typed `kind: "finding"` (replay `update_kind`); never infer it from text. Mount the
view in a container with a definite height (as `WorkflowChat` does) so its actions stay above
the composer; do not add controls or counters to it.
The view holds no settings: cue preferences belong in the host's settings.

Use `conversationReply` for a selected public update. For composed runs, pass only the
current server view’s run tree as its optional fourth argument; historical run IDs are excluded. Send the original human
words as `display_text` alongside guidance so durable accepted receipts preserve them.
Answer the exact pending question through the controller; never substitute guidance for
an approval. Essential questions wait indefinitely. Timed clarifications require a
120–300 second deadline and declared fallback; silence is not consent.

`onAttendedChange` suppresses host final narration while reading. Put microphone capture
in `voiceControl` and playback actions in `playbackControl`; capture interrupts speech,
playback pause/resume must retain its audio. Use existing voice transport. Scope
`useAvatarConversationPreferences` by account and preserve silent replay on reconnect.
See [panel-chat](https://raw.githubusercontent.com/lpalbou/AbstractUIC/main/panel-chat/README.md).
